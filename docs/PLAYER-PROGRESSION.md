# Player progression v1 (private casual pilot)
- Explicit additional per-round opt-in in setup. Existing history-only consent never earns XP. The player chooses Save round and earn XP, can withdraw the consent until the round ends, and is told that the aggregate persists until account deletion. Account deletion cascades progression; receipt expiry removes history but not the explicitly consented aggregate. No backfill.
- 10 XP per completed all-human round (2–5 humans, no bots); 50 XP per UTC day, same points regardless of placement. Daily cap is a bound, not a target or streak. No inactivity penalty, public ranking, spendable currency, premium access or paid advantage. Casual collusion is possible; never use these points for matchmaking, competitive ratings or real-world value.
- Level 1 starts at 0 XP; every 100 XP increases level. Achievements derive from rewarded rounds: First Stack (1), Table Regular (5), Table Veteran (25), Century Club (100). These are proposed tuning defaults, version 1. No historical recalculation on read.
- The room CAS, receipt, personal history and aggregate upsert share one SQL statement. No separate award endpoint or client-submitted XP. Per-account row upsert serializes concurrent caps; lock order by account UUID reduces deadlocks. UTC day never regresses on an older transaction. Stale revision and replay cannot award twice. If a database failure rolls back finalization, refresh and retry with authoritative room state. Verify real concurrent finalization before enabling.
- Requires shared database, all prior history/account/receipt gates, db/room-player-progression.sql, PILEHEAD_PROGRESSION_SCHEMA_READY=1 and PILEHEAD_PROGRESSION_ENABLED=1. Grant room runtime SELECT/INSERT/UPDATE on progression and SELECT(account_id) on player rounds; account runtime SELECT on progression. Account sessions gate all profile reads. No production activation or migration by this PR. Apply privacy notice, account deletion/retention review and real staging acceptance before release.
- Tests: pure snapshot and SQL contract; disposable PostgreSQL validates opt-in, bot exclusion, stale/replayed CAS, daily cap and UTC rollover simulation, receipt independence and cascading account deletion. Mobile/desktop mocked profile and consent UI. Live provider and real-device staging remain required.
