# Authoritative round receipt foundation
P1/P2 bridge; private room rounds only. Disabled by default. Not player-owned history, ranked play, or permanent anonymous tracking.
- Only a successful server-authoritative play → over transition produces a receipt. A data-modifying CTE makes the terminal room CAS and receipt insertion one atomic statement. Stale revision, invalid receipt or duplicate key cannot leave partially awarded history. Reading a finished round, a rematch, or withdrawal does not create historical records. No invented legacy history.
- Minimal allowlist: opaque UUID generated on first archived round, round number, versioned rules/scoring, format, human/seat counts, placements by seat, moves, server timestamps. No names, invite codes, tokens, private cards, IPs, analytics identifiers or raw events. UUID is carried in internal room JSON across rematches and excluded from public DTOs. Later identity linking must be server-authorized, not inferred from nickname or room code.
- Receipt rows survive room expiry independently, but expire after 90 days. No automatic pruning or migration is introduced here. Before activation, approve retention/privacy notice and configure bounded expiry-only deletion with a separate maintenance role. No new cron or paid resource.
- Apply db/room-round-receipts.sql to isolated PostgreSQL first. Grant existing room runtime INSERT and SELECT(room_instance_id) only, since SQL RETURNING needs that column. No runtime update/delete. Verify actual grants, index, expiry and privacy before applying production migration. Set PILEHEAD_ROUND_HISTORY_SCHEMA_READY=1 only after schema verification, then PILEHEAD_ROUND_HISTORY_ENABLED=1 after acceptance. Both must be set; unconfigured deployments use previous room update SQL unchanged.
- Enabling/disabling mid-room can yield partial round history; missing receipts are not losses or zero scores. Never derive ranked ratings or user-facing history from this incomplete pilot. Use immutable identity/roster links and full tournament completion gates next.
- Tests: pure receipt contract, real engine terminal move with simulated archive failure/retry, exact production SQL in disposable PostgreSQL (stale CAS, malformed/duplicate receipt rollback, runtime permissions). Full CI and physical device/live database acceptance pending.
