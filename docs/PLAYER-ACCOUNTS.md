# Persistent account storage foundation
Internal service only. No account endpoint or public login is exposed by this increment. Builds on guest profile schema; independent of game rules, room tokens, receipts, Stripe and entitlements.
- One UUID per verified Google provider subject (never match by display name or email). Atomic upsert, new session and previous-session revocation. Multiple devices retain their own sessions. SHA-256 token digests only; fixed 30-day server expiry. No email, Google access/refresh token or credentials stored.
- Internal account store requires the caller to verify provider identity before loginVerifiedIdentity; do not map it to an HTTP action or accept a client-asserted subject. Public projection excludes UUID, provider subject and tokens. Preferences and deletion query the authenticated, nonexpired session in the same SQL statement; explicit guest import copies preferences, not ownership or history, and does not delete the guest.
- Future provider adapter: Google OIDC authorization-code flow, state, PKCE and nonce; use a maintained JWT/OIDC library, not hand-written token verification, with pinned dependency and actual lockfile generated by npm. Validate issuer, audience, signature, expiration, nonce, authorized party and stable subject. Official references: https://developers.google.com/identity/openid-connect/openid-connect and https://developers.google.com/identity/gsi/web/guides/verify-google-id-token. Apply least scopes; verify real provider behavior in staging. Production provider configuration, secure cookies, rate limits, privacy notice, account deletion policy and recovery testing remain gates.
- Apply db/player-accounts-v1.sql only to isolated DB initially, alongside guest schema. Account DB role needs appropriate CRUD on account/session tables and only SELECT on guest profiles for import. Never use administrator credentials. Set explicit retention/deletion policy and bounded session expiry cleanup; no migration or feature activation in production by this change.
- Tests: exact SQL in disposable PostgreSQL validates verified subject reuse, multiple devices, token rotation, isolated accounts, explicit guest preference copy, expiration, logout and account deletion cascading all sessions. Pure tests validate digest-only parameters and public projection. No real OAuth exchange tested.

## Google OIDC adapter follow-up
- Uses pinned jose 6.2.18 for verified JWT signature, issuer, audience, required claims and token age; additional authorized-party and nonce checks. Fixed Google endpoints, authorization code with PKCE S256, HMAC-signed ten-minute state/verifier/nonce cookie and fixed callback. Account session cookie is Secure/HttpOnly/SameSite=Lax to permit session rotation on the cross-site Google callback; all non-callback API writes require exact same-origin JSON. No tokens or provider identifiers are exposed in JSON, logs or URLs after callback.
- The candidate dependency lock is pinned to the official npm tarball and a SHA-512 digest independently present in two public package locks; local npm registry lookup failed DNS. CI npm ci must verify the official tarball and security audit before merge. Reproduce npm lock metadata with npm when registry access is available.
- Account API and /profile panel remain disabled by default. Configure PILEHEAD_ACCOUNT_SCHEMA_READY=1 only after the account schema is verified in staging; PILEHEAD_PLAYER_SCHEMA_READY=1, PILEHEAD_PLAYER_DATABASE_URL, PILEHEAD_PLAYER_ORIGIN and reviewed PILEHEAD_PLAYER_PRIVACY_URL are also required. Configure PILEHEAD_GOOGLE_CLIENT_ID, PILEHEAD_GOOGLE_CLIENT_SECRET, an independent random PILEHEAD_ACCOUNT_FLOW_SECRET (at least 32 characters) and exact callback https://pileheads.com/api/account/callback in Google Cloud, then enable PILEHEAD_ACCOUNT_ENABLED=1 only after staged acceptance. Do not copy secrets into source. Account reads, logout and deletion remain possible when login is disabled but schema configured.
- Still required: actual Google authorization, cancellation, provider scope acceptance (openid only), two real browsers/devices, HTTPS cookie rotation, callback access-log redaction, public abuse limits and privacy/retention approval. No real OAuth exchange, production account activation or migration by this PR. No room/profile history linkage, ranked play, purchases or entitlements.
