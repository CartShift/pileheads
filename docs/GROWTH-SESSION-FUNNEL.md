# Consented session funnel (growth v2)

This is separate from the voluntary local playtest report and remains disabled by default. It records only fixed event flags for one temporary opted-in browser session: play opened, first observed round started/completed, requested rematch started, invite copied, successful room join, and result share/copy. Internal round keys, player names, room codes, card identities, raw URLs, IPs, and referrers are not included in application analytics.

Apply growth v1 and `db/growth-v2-funnel.sql` on an isolated database first. Only set server-side `PILEHEAD_FUNNEL_SCHEMA_READY=1` after migration, then `PILEHEAD_FUNNEL_ENABLED=1` after the owner has approved the actual privacy notice, consent UX, retention and abuse controls and verified end-to-end testing. Same approved privacy URL/version and operator token as growth v1. Do not enable by default in preview or production.

Consent is explicit, separate and optional; session credentials are kept in sessionStorage only after consent, expire for collection after 24 hours, and are not linked to any persistent visitor identity. Storage may be unavailable or cloned by the browser; this is not a unique-person count. Stop immediately stops new collection and requests deletion using the session token, even with collection disabled. If removal fails the UI offers retry before closing the tab. Retention cleanup (30 days, including backups according to agreed policy) is an operational gate, not implemented as an automatic job. No cross-day retention is measured. A queued request may be interrupted; delivery is best-effort, and the session funnel is not an audit log or authoritative server gameplay count. Server flags enforce event order and token scope, but opted-in clients are not trusted as proof against fraudulent traffic. Daily session cap and reviewed edge abuse controls are required before promotion.

Dashboard denominators: starts / play-opened sessions; completions / started sessions; observed user-requested rematch starts / completed sessions; room joins among invite-entry sessions (not a link-level invite conversion). Source/campaign are fixed category values captured after opt-in. Reports are self-selected and cannot estimate all traffic or unique players. Do not equate copied links or share API resolution with a publication or another user receiving it. Resumed or already-running rounds without observed setup are excluded. Results are observed completions and may be subsequently undone in local play; no claim of irrevocable completion.

Testing: unit tests cover event sequence and mock persistence; browser integration should verify no POST before consent, home-to-play measurement, actual round start and opt-out. Live Neon migration, real-device consent and deletion, failure/expiry handling and operator access are required before enabling. No tracking, migrations or paid infrastructure have been activated by this code change.
