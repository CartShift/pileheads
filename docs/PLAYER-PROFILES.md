# Player profile foundation — 2026-11-27
This is a scoped successor to the unmerged commercial PR #91. Reuse its guest session model, not its obsolete frontend, commerce, or Classic dependencies.
- Optional browser-bound guest profile: nickname and free deck preference. No verified account, room membership, match results, recovery, purchase wallet or cross-device identity. Explicit creation only; anonymous play unchanged.
- 256-bit random HttpOnly Secure SameSite=Strict host-only cookie; digest stored, never public UUID/token. Fixed 90-day expiry. Same-origin JSON POST, bounded body, allowlisted fields, no client-provided player IDs. No name or session logging. Deletion remains available when new creation is disabled, if the schema connection is configured.
- Shared DB-wide creation ceiling 250/day (atomic CTE); per-process request caps are only a preliminary abuse defense, not adequate for public traffic. An attacker can exhaust the global budget. Concurrent first-time requests from multiple tabs can create separate expiring rows. Verify quota concurrency and expiry before activation.
- No game engine/rules, room API, existing database schema, billing, or hosting changes. No production migration or flag activation by this PR.
- Explicit migration db/player-profiles-v1.sql against an isolated test database first. Use dedicated restricted role for only SELECT/INSERT/UPDATE/DELETE on the two tables as required (quota does not need DELETE in the runtime role); do not reuse an unrestricted admin connection. Do not copy secrets into source.
- Set PILEHEAD_PLAYER_DATABASE_URL, PILEHEAD_PLAYER_ORIGIN (canonical HTTPS origin, exact), PILEHEAD_PLAYER_SCHEMA_READY=1 after verification, PILEHEAD_PLAYER_PRIVACY_URL (reviewed, same-origin privacy notice), and finally PILEHEAD_PLAYER_ENABLED=1. Default disabled. If disabling new profiles, leave schema config in place for deletion. Set matching Vercel and Render environment only where used.
- Establish expiry and backup-retention process before enabling; prune expired profiles and old quota rows using maintenance role. No new cron or paid resource.
- /profile uses saved nickname/deck only when user explicitly selects Play with saved preferences; local game settings remain independent and may be changed. Guest profile does not authorize room commands.
- Acceptance gates: exact-head CI/build and /profile export, actual disposable PostgreSQL transaction/quota/expiry tests, Vercel HTTPS cookie and request-body tests, Render adapter smoke, real browser create/update/reload/delete, privacy notice and abuse/retention review. Do not enable publicly until these pass.
- Next: verified identity and transactional linking/recovery, durable authoritative tournament finalization and player-owned history, then matchmaking. Preserve room seat tokens as separate authorization. No client-reported competitive stats.
