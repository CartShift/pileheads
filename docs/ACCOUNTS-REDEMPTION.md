# Accounts and redemption (beta, disabled by default)

Google OpenID Connect authorization-code flow with PKCE, state, nonce, signed ID-token verification against Google JWKS and issuer/audience/time checks. Only the stable subject is persisted, no email, access or refresh tokens. OAuth credentials never reach client code. See https://developers.google.com/identity/openid-connect/openid-connect and https://developers.google.com/identity/openid-connect/reference.

Apply 001 through 004 migrations in a staging database. Configure a Google OAuth web application with exact redirect URI `<STACK_PLAYER_ORIGIN>/api/account/callback`. Set STACK_GOOGLE_CLIENT_ID, STACK_GOOGLE_CLIENT_SECRET and STACK_ACCOUNT_ENABLED=true only after staging review. STACK_PLAYER_ORIGIN must be HTTPS with no trailing slash. Sessions expire in 30 days. Returning users can sign in on other devices with the same Google account. Explicit guest deck import copies only preference, not game sessions or analytics; it does not delete the guest profile. No provider account linking or password recovery.

Redemption uses a single atomic PostgreSQL statement to consume a previously unredeemed code and create an entitlement. No client-selected product ID. Generate private batch codes via `node scripts/generate-redemption-batch.cjs batch-001 100 /private/new-directory`. Import only hash CSV columns into stack_redemption_codes via authorized DB tooling, never commit files, never issue real codes until staging concurrency tests pass. Current product is a demo founder supporter badge shown in the account page; no gameplay access, payment or premium artwork. Migration 004 serializes redemption and rejects already owned or revoked products without consuming the code. Revoked grants are not restored by a second redemption. Account deletion removes account sessions and entitlements; consumed code remains marked consumed. Do not enable purchases until refund/revocation, customer support, tax, privacy and account deletion requirements are resolved. Delete expired sessions and guest rows under approved retention process.

Test actual provider login, canceled consent, callback state/nonce/replay, session expiry, cross-device sign-in, concurrent redemption, database constraints, account deletion, cookie handling, offline gameplay and accessibility on staging. Provider tokens are never logged by this implementation; ensure infrastructure access logs do not record callback query parameters. Process-local rate limits are not sufficient for public commercial traffic. Feature flags off until release gates pass.
