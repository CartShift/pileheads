# Google Analytics 4 foundation
GA4 complements the existing first-party consented game funnel; neither consent implies the other. This phase measures public marketing routes and explicit links to play only, not gameplay, profile, growth dashboard or checkout. No dependency or backend secret is needed.

## Activation gate
1. Create a GA4 property PILEHEADS, web stream https://pileheads.com, EUR, Europe/Berlin. Copy the G- measurement ID.
2. Disable Enhanced Measurement in the web stream (including history pageviews, outbound clicks, site search and form interactions). Disable Google Signals, advertising personalization and Ads links. Review data retention (start with 2 months) and data collection settings.
3. Publish and approve a privacy notice covering Google Analytics, cookies, purpose, legal basis, recipients/transfers, retention and withdrawal. Review consent UI and data processing terms before enabling.
4. Production build settings only: NEXT_PUBLIC_GA4_MEASUREMENT_ID=G-..., NEXT_PUBLIC_GA4_PRIVACY_URL=https://... (actual approved notice), NEXT_PUBLIC_GA4_ENABLED=1. The ID is public, not a credential. Redeploy after build variable changes. Leave preview disabled; hostname also restricts execution to pileheads.com/www.
5. Verify in browser DevTools, Tag Assistant and GA4 DebugView/Realtime: no Google request/cookie before consent or after rejection; accept, one manual page_view per navigation, play_cta_click for actual links; withdraw and confirm requests cease and GA cookies are cleared. Test rapid route changes, back/forward, multiple tabs, reloads, mobile/PWA, script blockers, and invite/profile routes with synthetic sensitive query strings. Inspect all Google requests for raw URLs/referrers or room codes. Do not enable for public traffic until these checks pass. Disable the flag immediately if unexpected collection occurs.

Known limitations: initial pageview is collected only after opt-in; known fixed UTM categories are preserved, other campaign parameters are intentionally dropped; query-only navigations do not emit pageviews. Consent persists locally, separate from gameplay consent; withdrawal stops future measurement and attempts removal of standard first-party GA cookies, not deletion of already collected Google data. Client navigation disables GA outside marketing pages; browser verification is mandatory to confirm vendor automatic events do not bypass the intended boundary. No marketing or advertising tags are enabled. Consent UI placement and full browser testing remain to be reviewed.

## Future event contract
Add independently consent-gated, allowlisted product events after browser validation: tutorial_complete, game_start, game_complete, rematch_start, invite_share (copy/share is not successful delivery), sign_up, login. Keep room codes, player names, account IDs, tokens, raw URLs and free text out. Use GA4 recommended ecommerce events view_item, add_to_cart, begin_checkout, purchase with non-personal item IDs, currency and confirmed unique transaction IDs. Never send payment credentials; avoid duplicate purchase events. No ecommerce or gameplay events are implemented in this phase. The existing first-party session funnel remains unchanged.

## Isolated browser acceptance
The full CI build uses a synthetic G-CITEST0001 measurement ID only. The GA4 Playwright test fulfills the production-looking origin from the local static export, blocks external requests and substitutes a no-op Google script. This checks our client-side integration without sending traffic to Google. It does not replace testing actual Google tag network behavior on the approved production configuration. Do not deploy the CI-only synthetic build to production.

The two exact historical fingerprints are in `.gitleaksignore`; a full history scan passed with those exceptions. No rule, path, branch or class of secrets is excluded.
